# Gate (rename + resolver + onGate) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename "Browse Gate" → "Gate", add a per-request `GateResolver` (decides gate/allow per browse-or-search request, with optional per-request chrome), and add an `onGate` notification event — all on the four existing car-only enforcement sites.

**Architecture:** The gate stays global imperative state. `setGate` records a default chrome and (optionally) a resolver. At each of the four enforcement sites (iOS CarPlay browse + Siri search; Android Auto `onGetChildren` + `onSearch`) the site asks the bridge for a gate decision for the current request; if gated it serves the gate chrome (default, per-request override, or a built-in minimal fallback) and fires `onGate`. The resolver is surface-independent and runs _before_ the content cache, so no cache changes are needed.

**Tech Stack:** TypeScript (Yarn 4 / `corepack yarn`), Nitro codegen, Swift (iOS), Kotlin (Android), web stub. Source of truth: `docs/superpowers/specs/2026-06-23-gate-design.md`.

- **Final API surface (from the spec):**

  ```ts
  type Gate         = { title: string; message?: string; buttonTitle?: string; onButtonPressed?: () => void }

  setGate(resolve: GateResolver): void
  clearGate(): void
  onGate?: (event: { reason: 'browse' | 'search' }) => void
  ```

## Task 1 — outcome

**Status: LOCKED**

### Q1 — `onSearch(query): Promise<Track[]>` direction and mechanism

`onSearch` is **JS→native** (a method on `HybridAudioBrowserSpec`). Native implements it; JS calls it. It is not a callback property. Evidence:

- `src/specs/audio-browser.nitro.ts:99` — declared as a method (not a property) on the spec interface.
- `ios/HybridAudioBrowser.swift:433` — native implementation: `public func onSearch(query: String) throws -> Promise<[Track]>`.
- `android/.../AudioBrowser.kt:648` — `override fun onSearch(query: String): Promise<Array<Track>>`.
- `nitrogen/generated/ios/swift/HybridAudioBrowserSpec_cxx.swift:1580` — the cxx bridge marshals the return through `bridge.create_Result_std__shared_ptr_Promise_std__vector_Track____()`.

**`onSearch` is NOT the pattern for `resolveGate`** — it runs in the wrong direction (JS→native, not native→JS).

### The correct precedent: value-returning native→JS callbacks in structs

The real pattern lives in `NativeBrowserConfiguration`. Fields like `resolveAlbumUrl`, `formatNavigationError`, and `searchCallback` (on `NativeRouteEntry`) are native→JS callback properties typed as `(Params) -> Promise<T>`. How native awaits them:

- **iOS:** `try await resolver(params).await()` — `resolver(params)` returns a Swift `Promise<T>` that wraps the JSI promise; `.await()` suspends the current `async` task until JS resolves it. (`ios/CarPlay/CarPlayNowPlayingManager.swift:240`, `ios/CarPlay/CarPlayController.swift:607`)
- **Android:** `formatter(params).await()` — single await inside a coroutine scope. (`android/.../AudioBrowser.kt:453`)

### Q2 — Nitro callback properties returning `Promise`

**Confirmed: fully supported.** Evidence:

- `nitrogen/src/syntax/types/FunctionType.ts:16-23`: Nitro codegen automatically wraps any non-void callback return in `Promise`. If you write `resolveGate: (r: GateRequest) => GateDecision`, codegen internally produces `(r: GateRequest) => Promise<GateDecision>`. The TS spec declaration `=> Promise<GateDecision>` is thus the correct explicit form (matches what codegen does).
- `Sync<T>` wrapper (from `react-native-nitro-modules/src/Sync.ts`) forces synchronous invocation with no Promise wrapping. It works by tagging the function type with `__syncTag`.
- **Sync is viable at the codegen level**, but the design doc explicitly rejects it (`docs/superpowers/specs/2026-06-23-gate-design.md`: "The resolver is a synchronous native→JS call… Nitro/JSI supports sync callbacks") — however, the existing precedent (all value-returning native→JS callbacks in this codebase) uses async/Promise. Sync callbacks require calling from the JS thread and block it; the serve paths (CarPlay handler, `scope.future{}`) are async and already have watchdogs — async fits without thread-safety concerns.

### Q3 — Recommendation

**Bridge form: `resolveGate: (request: GateRequest) => Promise<GateDecision>`** (async, explicit).

Rationale:

- Mirrors the established native→JS value-returning pattern (`resolveAlbumUrl`, `formatNavigationError`, `searchCallback`). No new codegen territory.
- iOS serve paths are already `async` (CarPlay handler, Siri intent handler). Android serve paths are already in `scope.future{}` coroutines. `await resolveGate(request).await()` / `resolveGate(request).await()` drops in directly.
- Sync (`Sync<(r) => GateDecision>`) would require calling from the JS thread; the serve threads are not the JS thread. Using async avoids thread constraints entirely.
- The design doc note ("synchronous native→JS call") was written before this spike; the async await pattern is equally fast (no network in the resolver) and safer.

**`GateRequest` shape: flat struct** — do NOT use the object-union form.

Rationale:

- Nitro encodes TS object-unions as `std::variant<A, B>` → Swift `enum { case first(A); case second(B) }` with **positional** `.first`/`.second` cases. The `kind` discriminant string would be structurally dead in native (native switches on case, not the field). That is confusing and inconsistent with the rest of the codebase.
- No existing spec type is an object-union. All multi-field event types are flat structs (`RemotePlaySearchEvent`, `NavigationErrorEvent`, etc.).
- **Use a flat struct:** `interface GateRequest { reason: 'browse' | 'search'; path?: string; search?: SearchParams }`. The `reason` field becomes a Nitro enum. This matches `GateEvent` (`{ reason: 'browse' | 'search' }`) and the existing `*Event` convention.

**`GateDecision` / `GateEvent` / `NativeGate` viability:**

All are simple flat structs — no issues. `GateDecision: { gated: boolean; gate?: NativeGate }` is fine. `GateEvent: { reason: 'browse' | 'search' }` — `reason` becomes a Nitro enum (string-literal union declared as a named type). `NativeGate: { title: string; message?: string; buttonTitle?: string }` is straightforward.

### Q4 — Impact of flat-struct choice on Tasks 2–6

The plan uses `{ kind: 'browse'; path: string } | { kind: 'search'; params: SearchParams }` throughout. Change every occurrence of this object-union to the flat struct:

**Task 2 (spec):** Replace the `resolveGate` signature in `src/specs/audio-browser.nitro.ts`. Use `GateRequest` as a flat interface (not a union). Add a `GateReason = 'browse' | 'search'` string-literal enum type.

**Task 3 (gate.ts):** `GateRequest` type definition changes from union to flat struct. The resolver parameter `(request: GateRequest)` still works the same — callers check `request.reason === 'browse'` instead of `request.kind`. The test in Task 3 changes `{ kind: 'browse', path: '/x' }` → `{ reason: 'browse', path: '/x' }` and `{ kind: 'search', params: ... }` → `{ reason: 'search', search: ... }` (field name `search` not `params` to avoid conflict — decide at implementation time, spike recommends `search`).

**Task 4 (iOS):** At CarPlay browse site, build `GateRequest(reason: .browse, path: path, search: nil)`. At Siri search site, build `GateRequest(reason: .search, path: nil, search: params)`. No variant switching needed.

**Task 5 (Android):** Same: `GateRequest(reason = GateReason.BROWSE, path = parentId, search = null)` and `GateRequest(reason = GateReason.SEARCH, path = null, search = params)`.

**Task 6 (web stub):** `resolveGate` receives flat `GateRequest`. No variant handling needed.

**No other tasks are affected.** The `Promise<GateDecision>` async form was already the "preferred" form in the plan — no signature change needed there.

```ts
import { nativeBrowser } from '../native'
import type { SearchParams } from '../types/browser'

// MARK: - Types

/** The wire shape of the gate chrome (crosses the bridge). Button callback stays in JS. */
export type NativeGate = {
  title: string
  message?: string
  buttonTitle?: string
}

/** A gate's chrome plus its JS-only button handler. */
export type Gate = NativeGate & {
  onButtonPressed?: () => void
}

/** What the resolver is asked about. */
export type GateRequest =
  | { kind: 'browse'; path: string }
  | { kind: 'search'; params: SearchParams }

/** Decide per request: a Gate (gate with this chrome), true (default/built-in), false (allow). */
export type GateResolver = (request: GateRequest) => Gate | boolean

/** Wire form of a resolver result. */
export type GateDecision = { gated: boolean; gate?: NativeGate }

/** Fired when a request is gated. */
export type GateEvent = { reason: 'browse' | 'search' }

// MARK: - Built-in fallback chrome (for resolver `true` with no default)

const BUILT_IN_GATE: NativeGate = { title: 'Unavailable' }

// MARK: - Internal state

let defaultChrome: NativeGate | undefined
let buttonHandler: (() => void) | undefined
let resolver: GateResolver | undefined

nativeBrowser.onGateButtonPressed = () => buttonHandler?.()

// The native→JS resolver bridge. Native calls this per request at a serve site.
nativeBrowser.resolveGate = async (
  request: GateRequest
): Promise<GateDecision> => {
  const result = resolver ? resolver(request) : true // no resolver → static gate → always gated
  if (result === false) return { gated: false }
  if (result === true) return { gated: true } // native uses defaultChrome, or built-in if none
  const { onButtonPressed, ...nativeGate } = result // a Gate override
  buttonHandler = onButtonPressed ?? buttonHandler
  return { gated: true, gate: nativeGate }
}

// MARK: - Public API

export function setGate(gate: Gate, resolve?: GateResolver): void
export function setGate(resolve: GateResolver): void
export function setGate(a: Gate | GateResolver, b?: GateResolver): void {
  if (typeof a === 'function') {
    defaultChrome = undefined
    buttonHandler = undefined
    resolver = a
    nativeBrowser.setGate(undefined, true)
  } else {
    const { onButtonPressed, ...nativeGate } = a
    defaultChrome = nativeGate
    buttonHandler = onButtonPressed
    resolver = b
    nativeBrowser.setGate(nativeGate, b != null)
  }
}

export function clearGate(): void {
  defaultChrome = undefined
  buttonHandler = undefined
  resolver = undefined
  nativeBrowser.clearGate()
}

// Test-only hook for the resolver bridge.
export const __resolveGateForTest = (request: GateRequest) =>
  nativeBrowser.resolveGate(request)
```

## Controller note (post-Task-1) — supersedes the spike's "kind→reason in public API"

Locked: async `resolveGate: (req) => Promise<GateDecision>`. Nitro object-unions become positional `std::variant` in Swift, so **WIRE types are flat structs**; the **PUBLIC API keeps the discriminated union**, and `gate.ts` converts (mirrors the existing `NativeGate`/`Gate` split). `kind` stays in the public union; `reason` is wire-only.

**WIRE types** (defined in `gate.ts`, imported by the spec):

```ts
export type NativeGate = {
  title: string
  message?: string
  buttonTitle?: string
}
export type NativeGateRequest = {
  reason: 'browse' | 'search'
  path?: string
  search?: SearchParams
}
export type GateDecision = { gated: boolean; gate?: NativeGate }
export type GateEvent = { reason: 'browse' | 'search' }
// spec: resolveGate: (request: NativeGateRequest) => Promise<GateDecision>
```

**PUBLIC types** (consumer-facing, `gate.ts`):

```ts
export type Gate = NativeGate & { onButtonPressed?: () => void }
export type GateRequest =
  | { kind: 'browse'; path: string }
  | { kind: 'search'; params: SearchParams }
export type GateResolver = (request: GateRequest) => Gate | boolean
```

`gate.ts` converts `NativeGateRequest`→`GateRequest` before calling the consumer resolver, and maps the result→`GateDecision`. **Native owns the default/built-in chrome** — for `true`, JS returns `{ gated: true }` with no `gate`, and native applies its stored default (or the built-in fallback).

**Native→JS Promise-callback precedent:** `resolveAlbumUrl` / `formatNavigationError` / `searchCallback` on `NativeBrowserConfiguration` — `try await cb(x).await()` (iOS), `.await()` in coroutines (Android).
