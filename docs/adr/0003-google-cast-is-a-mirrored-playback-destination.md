# Google Cast is a mirrored playback destination, not an audio route

**Status:** accepted

Google Cast is modelled as a **playback destination** (see `CONTEXT.md` → "Playback destinations"): a cross-platform subsystem (compiled in by default, opt-out for size-sensitive apps) that moves *where audio plays* off the phone and onto a **Cast device**, while the **Queue**, **Active Track**, and **Now Playing** keep their meaning. It is deliberately kept distinct from **External surfaces** (which control/display while audio stays local) and from the iOS **Output**/AirPlay route API (a system audio route, where the phone keeps fetching the bytes).

A single, flat, cross-platform `Cast` API (`configureCast`, `getCastState`, `useCastState`, `onCastStateChanged`, `showCastPicker`, `isCasting`, `getCastDeviceName`, `endCastSession`) is added to the existing `AudioBrowser` HybridObject, mirroring the `Ios*` output API shape. The two platforms share vocabulary and the JS contract but diverge entirely in mechanism, because Cast itself differs by platform:

- **Android** — `CastPlayer` *is* a Media3 `Player`. On session connect the `MediaLibrarySession`'s player is repointed at `InterceptingPlayer(castPlayer)` via `MediaSession.setPlayer()`; on disconnect it is repointed back at the local `InterceptingPlayer(exoPlayer)`. The local ExoPlayer and its subsystems (buffering, EQ, stuck-recovery, `TransformingDataSource`, retry) go dormant while casting.
- **iOS** — there is no swappable player object. The `PlaybackCoordinator` keeps its `AVPlayer` but, while a Cast session is live, **suspends local playback and routes transport + queue-load to `GCKRemoteMediaClient`**; position/state come from the remote client's callbacks. The facade is the single place that knows "local vs remote".

The full **Queue** is mirrored onto the receiver. Each queued item carries the app's stable Track identity in its Cast `customData`, and media (and `target: 'cast'` artwork) URLs are signed at load time. Because signed URLs expire over multi-hour live sessions, expiry is handled **reactively and bounded**: when the receiver hits a stale-URL load error, the sender JIT re-resolves *that one item* and updates it on the receiver (`RemoteMediaClient.queueUpdateItems`), capped to avoid an infinite reload loop on a genuinely dead stream.

Cast is **compiled in by default and gated at runtime**: the SDK links by default, but Cast stays **inert until the app calls `configureCast()`** (Update, see below — this reverses the original build-time opt-in). Size-sensitive apps that never cast can **opt out at build time** (Android `AudioBrowser_enableCast=false` selects an inert sourceset; iOS `AUDIOBROWSER_DISABLE_CAST=1 pod install` drops the pod + the Swift active-compilation condition), linking no Cast SDK. The library ships its own Cast `OptionsProvider` (Android) / calls `setSharedInstanceWith` (iOS), reading the receiver application ID supplied to `configureCast()` from a static holder set *before* the Cast context initialises; an omitted ID defaults to Google's Default Media Receiver.

## Considered options

- **Model Cast as another External surface.** Rejected: `External surface` has one clean trait — audio plays *locally* while the surface browses / displays / sends Remote commands. A Cast device is where audio *plays*. Folding it in would muddy the term; a Cast device that happens to emit Remote commands is a destination first.

- **Android: a permanent coordinator / `ReplaceableForwardingPlayer` instead of `setPlayer`.** Rejected. The coordinator's appeal is that the session and its listeners never see the player instance change — but its hard part (firing synthetic timeline / position-discontinuity / tracks listener events on every swap so all state-caching consumers stay correct) is exactly what `MediaSession.setPlayer()` already does internally, including renotifying connected controllers across the process boundary. The queue+position transfer is identical either way, so the coordinator buys re-implementation of a solved problem. `setPlayer` also matches our existing "engine generation swap" model in `Player.kt`, and `InterceptingPlayer` keeps wrapping whichever player is active, so `handleRemote*` interception works on Cast for free. Cost accepted: `PlayerListener`/`NowPlayingUpdater` must explicitly follow the active player (detach/attach on swap, read through an `activePlayer` accessor) — explicit and testable, which we count as a virtue.

- **Mirror only the current item to the receiver ("single-item").** Rejected despite being simpler and making URL expiry structurally impossible. With one item on the receiver, **external transport (voice "next", Google Home app, TV remote) has nothing to skip to** and full-queue rehydration on relaunch is impossible. TV casting is a first-class use case, so external next/prev and resumable queues are worth the cost of reactive re-signing. (The receiver's *visible* now-playing card is identical either way; the Default Media Receiver renders no up-next list regardless.)

- **Eager full-queue resolution with no re-signing.** Rejected: signed URLs expire over multi-hour live sessions, so items deep in the mirrored queue would be dead by the time the receiver reaches them. Reactive, bounded re-signing keeps every fetched URL fresh-enough while preserving the mirror.

- **A dedicated `castMedia` resolver / request-config layer.** Rejected in favour of a `target: 'local' | 'cast'` discriminator on the existing media (and artwork) transform params. The receiver fetches media and artwork itself, so per-request **header** auth does not cross the boundary — only URL-embedded (query-signed) auth survives. The discriminator lets an app's *existing single transform* branch to emit a self-contained, receiver-fetchable URL, reusing one resolution pipeline instead of forking it.

- **Runtime `configure()` vs a build-time receiver-app-ID constant.** Chose runtime `configureCast()`: one cross-platform entry point, a sane default (Default Media Receiver), and the ability to select a custom styled receiver from JS without a native rebuild. The "set a static holder before `getSharedInstance`" trick is small and well-trodden. Note the receiver app ID is bound at *first* `configureCast()` and cannot change for the process lifetime — both `GCKCastContext.setSharedInstanceWith` (iOS) and `CastContext.getSharedInstance` (Android, which reads the holder once) initialise once. A later `configureCast()` with a different ID is ignored (with a warning); the choice is per-launch, not live-swappable.

- **Ship a native `<CastButton/>` component.** Deferred. The library is deliberately imperative and has no native view components; `showCastPicker()` presents the chooser on both platforms (`MediaRouteChooserDialog` / `presentCastDialog()`), mirroring `openIosOutputPicker()`. The app draws and styles its own button. Device **discovery** is therefore driven by the library, ref-counted to live `onCastStateChanged` subscribers / mounted `useCastState()` consumers, rather than coupled to a button's view lifecycle.

- **Generalise to a destination-agnostic abstraction now (anticipating Sonos).** Rejected. Sonos shares the *destination* concept and the self-contained-URL constraint, but nothing of the mechanism (no Media3 `SonosPlayer`; a separate UPnP / cloud Control API with its own OAuth and discovery). Building a god-abstraction against one real backend is speculative generality; the shared seam is extracted when a second real backend (Sonos) provides the data point. `target` stays `'local' | 'cast'` until then.

## Consequences

- **The default build links the Cast SDK but stays behaviorally inert until `configureCast()`.** A consumer who never calls `configureCast()` behaves exactly as today (the runtime gate keeps everything off); it just carries the SDK in the binary. An opt-out build (size-sensitive apps) compiles the inert sourceset / `#else` no-ops and links nothing.

**Update (supersedes the original build-time opt-in):** Cast was first shipped **opt-in** (off by default, enabled via the build flag) to spare non-casting apps the Cast/Play-Services weight. That made enabling Cast a three-step per-platform dance (Gradle flag + an *ephemeral* `pod install` env var + `configureCast()`), which was poor DX for the primary consumer (Radio Garden, which always casts). We flipped to **default-on + runtime gate + opt-out flag**: the runtime `configureCast()` gate already provides the real safety (inert until called), so the build flag was a redundant second gate that added friction. Enabling Cast is now just `configureCast()` + the unavoidable iOS `Info.plist` keys; the opt-out flag preserves the zero-weight path for apps that need it.

- **`Player.kt` (Android) grows an "active player" seam.** `PlayerListener` and `NowPlayingUpdater` follow the active player across swaps; local-only subsystems gate on "am I local right now?". `Player` exposes an `activePlayer` accessor that the now-playing surface and timers read.

- **Cold-relaunch-while-casting rehydrates the full queue** by reading each receiver `MediaQueueItem`'s `customData` back and re-resolving Tracks via `BrowserManager`. The only unrecoverable state is the in-flight Now Playing *override* text (the current ICY song), which re-arrives from the stream on reconnect.

- **Live metadata on the receiver is best-effort.** Rich station metadata + artwork is pushed at load; mid-stream `updateNowPlaying()` is pushed via the cheap in-place path (live on Android, best-effort on iOS) and **never** triggers a stream reload — a reload would drop live audio. Artwork is resolved once at load and not reactively re-signed (a broken image is a smaller harm than dead audio).

- **EQ is inert while casting** (local DSP on audio that isn't on the phone); **volume routes to the Cast device**; the **sleep timer** still fires (pauses the Cast player) but skips its local `VolumeFader` ramp.

- **The app must add platform Cast plumbing the library cannot hide:** iOS `NSLocalNetworkUsageDescription` + `NSBonjourServices` (and the iOS 14+ local-network permission prompt), and the Android `consumer-rules.pro` keep for the reflectively-instantiated `OptionsProvider`. These are documented, not abstracted away.

- **A second CI build variant** (Cast-enabled) is needed to keep the conditionally-compiled sourceset / podspec guard green.
