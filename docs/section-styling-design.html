Section Styling — the worked design

react-native-audio-browser · August 2026 · companion to the CarPlay SDK audit. How sections and tracks declare presentation: style declaration blocks with a cascade — the CSS-adjacent model — plus the full property set and the alternatives that were tried and rejected on the way here.
Status: decided design, not implemented. The branch currently ships style: 'list' | 'grid' | 'rail' (string) on Section and style: 'list' | 'grid' on Track. This document specifies the successor: style becomes a declaration block on both, with per-property cascade. The audit report's decisions panel has been amended to match; where any residual wording disagrees, this document is the later word. Revised after a three-review pass (API design, implementation feasibility, coherence) — see §7/§8 for what the reviews changed.

1. The model: style is a declaration block

/**
 * The properties a Track may carry: the *cascading item properties*
 * (resolved `track ?? section ?? page ?? default`, per property —
 * they travel with the track: a favorited artist keeps its circular
 * shape in whatever grid renders it next) plus the *positional*
 * `display` (each holder's own children; never cascaded).
 *
 * **The inheritance boundary**: a handle's block styles the handle;
 * a page's block defaults the page's descendants; nothing inherits
 * across resolution (a circular artist handle must not make the
 * albums inside its page circular). The only thing that crosses is
 * `display`'s pre-resolution promise — a hint emission, not
 * inheritance. Admission test for any future property: "if set on a
 * browsable parent, do I really want its resolved descendants to
 * inherit it unless overridden?" — within a page, yes for every item
 * property; across resolution, never.
 *
 * Rules governing every property in both blocks:
 *
 * - **Declarations are aspirational.** Each surface renders the
 *   properties it understands and ignores the rest. A property a
 *   surface can't render and a property the current `display` doesn't
 *   use are ignored identically — inert, never an error.
 * - **Inheritance.** The item properties (Apple element
 *   *parameters* — knobs on one tile/row) cascade
 *   `track ?? section ?? page ?? default`. Container properties
 *   (element *classes* and item-level knobs) resolve
 *   `section ?? page ?? default`. `display` is positional — each
 *   holder describes its own children — and never cascades
 *   item-to-container.
 * - **Presentation only.** No style property ever affects queue
 *   scope, playback, or navigation (ADR 0006/0010): rendering may
 *   truncate what is visible, it never changes what plays. (This is
 *   why `disabled` is NOT here — it swallows taps, so it lives on
 *   Track as a state fact.)
 * - **Degradation drops decorations before layout, where the layout
 *   is renderable at all**: a treatment the surface can't render
 *   falls to the nearest rendering that keeps the layout (pre-26
 *   card shelf → legacy tile row, not a list), and declaring a
 *   decoration never changes the layout you'd get without it. The
 *   one layout drop: a *wrapping* grid pre-26 has nowhere to go but
 *   a list (its only tile container is single-line).
 * - **Update semantics**: style is honored at page (re-)serve.
 *   In-place element mutation is an internal optimization the
 *   library may apply where verified, never a promise.
 *
 * `@platform` marks the *surface* whose library renderer acts on a
 * property today (`carplay`, `android-auto`); consumer-rendered UIs
 * may honor any property on any platform.
 */
interface TrackStyle {
  /**
   * How this entity's *children* lay out — CSS's inner display type,
   * honored literally (`display: 'grid'` in CSS describes the
   * children, not the element). The meaning is uniform at every
   * position; only the children differ:
   *
   * - On a **Section** (via `extends`): the section's children.
   * - On a **resolved page** (`ResolvedTrack.style`): the page-wide
   *   default its sections fall back to.
   * - On a **browsable Track** (the handle): the layout *promise*
   *   for the page it opens — consumed by Android Auto's
   *   parent-level content-style hint, the one reader that acts
   *   before the page resolves (and, on AOSP-derived AAOS media
   *   UIs, the only below-root hint honored at all — per-item
   *   hints are ignored there; source-verified in research).
   * - On a track rendered *playable* (src wins the rendering):
   *   inert — playables open no page.
   *
   * **Not part of the item cascade** — each holder speaks only for
   * its own children. A section's layout resolves
   * `section.display ?? page.style.display ?? 'list'`. The handle's
   * value is the pre-resolution promise: **declared or it doesn't
   * exist** (no value → no parent-level hint emitted — the library
   * never derives a promise from pages it hasn't resolved, and never
   * back-fills from ones it has: rendering stays stateless). The
   * resolved page is the truth; the hint is frozen at serve, never
   * re-emitted. A targeted dev warning fires at the one failure
   * site: Android serving a page whose sections say grid under a
   * parent item that carried no promise.
   *
   * - `'list'` (default) — full-width rows on every surface.
   * - `'grid'` — artwork tiles; wraps unless `gridWrap: false`.
   *   Tiles presume artwork.
   *
   * @default 'list'
   *
   * @see https://developer.android.com/training/cars/media/create-media-browser/content-styles
   */
  display?: 'list' | 'grid'

  /**
   * SF Symbol name drawn as the item's accessory — trailing on list
   * rows, leading the title on grid tiles (placement is the
   * platform's, per surface; there is no API to choose it). An
   * explicit symbol replaces the derived disclosure chevron on
   * browsable rows. `'none'` clears an inherited section value (the
   * cascade has no other escape: absent means inherit; no SF Symbol
   * is named bare `none`, so the sentinel is collision-free).
   *
   * Values are Apple's SF Symbol names — platform vocabulary no
   * naming can neutralize; silently ignored on every non-CarPlay
   * surface.
   *
   * Inheritable: per item (a lock on one child), or section-wide via
   * the section default (a locked section badging every child, with
   * `'none'` on the exceptions).
   *
   * @default undefined — no accessory (browsable rows keep the derived chevron)
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/carplay/cplistitem/accessoryimage
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitemimagegridelement/accessorysymbolname
   */
  accessorySymbol?: string

  /**
   * How the artwork bitmap is rendered. `'stencil'` uses the
   * artwork as a stencil — shape from alpha, color supplied by the
   * surface per appearance (Apple's template-image rendering,
   * `RenderingMode.alwaysTemplate`; screen-printing lineage for the
   * name) — the one-fetch alternative to a light/dark
   * `ArtworkVariants` pair for monochrome glyphs and logos.
   * `'original'` renders the bitmap's own colors.
   *
   * Named `artworkRendering`, not `imageRendering`: `image-rendering`
   * is a shipped CSS property (scaling algorithm) — the same
   * collision rule that renamed `grid-row` — and this is a
   * library-defined name, which per the glossary takes the role word
   * (`artwork`), not the generic one.
   *
   * Inheritable: per item, or section-wide via the section default
   * (a section of station glyphs, tinted uniformly).
   *
   * Replaces the flat `artworkCarPlayTinted` field.
   *
   * @default 'original'
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/uikit/uiimage/renderingmode
   */
  artworkRendering?: 'original' | 'stencil'

  /**
   * The mask applied to tile artwork.
   * `'circular'` is the convention for people — artists, hosts.
   *
   * Inheritable: the section's value is the section-wide default; a
   * child's own value overrides it per item — shape follows the
   * *kind* of item (a mixed search-results grid renders artists
   * circular next to rounded albums, and a person stays circular
   * wherever it travels).
   *
   * Bare name — the one true passthrough in the artwork group
   * (mirrors Apple's `imageShape` exactly), and the prefix rule is
   * *prefix only when meaningless outside one mode*: shape applies
   * to plain and `'condensed'` tiles alike (`'card'` tiles have no
   * shape; CarPlay list rows have no shape API today).
   *
   * @default 'rounded-rectangle'
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitemimagegridelement/imageshape
   */
  imageShape?: 'circular' | 'rounded-rectangle'

  /**
   * Card color. Grammar, pinned so three native parsers agree:
   * `#RGB` | `#RRGGBB` | `'none'` (the `sf:` scheme's parser is
   * 3/6-digit; alpha `#RRGGBBAA` is a planned future extension).
   * A string outside the grammar is treated as absent — inert,
   * never an error, never black. The color is the gradient at the
   * bottom of the card, or the color behind the labels when
   * `cardImage` is `'background'`. `'none'` clears an inherited
   * value back to the platform's standard coloring. Tints must read
   * on both appearances (no light/dark pair yet — `ArtworkVariants`
   * is the model if a consumer ever needs one).
   *
   * Card-prefixed like `cardImage` — within a block, property
   * families share a prefix (as CSS's `border-*` / `grid-*` do), and
   * the prefix states the inertness condition in the name.
   *
   * Rendered by: CarPlay iOS 26+. Inert unless the owning section's
   * `gridTile` is `'card'`.
   *
   * @default undefined — the platform's standard card coloring
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitemcardelement/tintcolor
   */
  cardTint?: string

  /**
   * How a card renders its artwork.
   *
   * - `'normal'` — artwork above, text in a footer over the
   *   `cardTint` gradient.
   * - `'background'` — the artwork becomes the card's backdrop,
   *   text overlaid, with `cardTint` as the color behind the labels
   *   (the tint flips roles because the image took the background).
   *   Selects the larger artwork target size — the artwork pipeline
   *   reads this.
   *
   * Inheritable: an element-level parameter like `cardTint` — set on
   * the section for a uniform row, per card to mix (one full-bleed
   * hero among normal cards is API-legal; taste is the author's).
   *
   * Rendered by: CarPlay iOS 26+. Inert unless the owning section's
   * `gridTile` is `'card'`.
   *
   * @default 'normal'
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitemcardelement/showsimagefullheight
   */
  cardImage?: 'normal' | 'background'
}

/**
 * A section's presentation: the *container* properties below, plus —
 * via `extends` — a section-wide default for every cascading item
 * property (and the section's own positional `display`). That a section can default anything a track
 * can declare is structural in TypeScript; Nitro flattens `extends`
 * into independent structs, so a cascade-completeness test (every
 * TrackStyle key read by every platform resolver) is part of the
 * spec, not an implementation detail.
 */
interface SectionStyle extends TrackStyle {
  /**
   * Whether the tiles wrap to multiple lines. `false` renders
   * exactly one line — the teaser shelf: a preview of a larger
   * collection, typically paired with `Section.path` as the
   * "view all" target and a subset of children.
   *
   * Rendered by: CarPlay (single-line row of tiles with titles and
   * subtitles on iOS 26+; the legacy single-line image row before
   * that — including for card/condensed treatments the older OS
   * can't draw, per the degradation rule: decorations drop, layout
   * survives). Android Auto has no single-line tile container — its
   * grid wraps, showing more, never less. Phone UIs typically honor
   * `false` as a horizontal scroller.
   *
   * A boolean by owner's choice (documented exception to the
   * enum-names-the-axis rule); the CSS word (`flex-wrap`).
   * Inert unless `display` is `'grid'`.
   *
   * @default true
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitem (`allowsMultipleLines`)
   */
  gridWrap?: boolean

  /**
   * Tile treatment — which cell the tiles render as.
   *
   * - `'plain'` (default) — plain artwork tiles. Exists as a value
   *   (not just absence) so a section can escape a page-level
   *   treatment — the cascade's only escape is an expressible
   *   default.
   * - `'card'` — large editorial cards: artwork with a text overlay
   *   or footer, colored via `cardTint` (inheritable — section-wide
   *   or per child), with `cardImage: 'background'` for full-bleed
   *   artwork. With `gridWrap: false`, this is the classic featured
   *   "hero row".
   * - `'condensed'` — a denser cell carrying title + subtitle.
   *   Note: currently the only way a *wrapping* grid shows
   *   subtitles (regular grid tiles have no subtitle slot) — a
   *   content-visibility effect riding a density knob, named here
   *   so it is at least discoverable. (Layout is otherwise the
   *   platform's; Apple documents only the word.)
   *
   * One treatment per section: the underlying containers are
   * homogeneous — a section cannot mix card and plain tiles. Mixed
   * treatments = two sections, which is the honest data model
   * anyway.
   *
   * Rendered by: CarPlay iOS 26+ (pre-26: the treatment drops,
   * `gridWrap` decides between legacy tile row and list). Inert
   * unless `display` is `'grid'`.
   *
   * @default 'plain'
   *
   * @platform carplay
   *
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitemcardelement
   * @see https://developer.apple.com/documentation/carplay/cplistimagerowitemcondensedelement
   */
  gridTile?: 'plain' | 'card' | 'condensed'
}

interface Section {
  title?: string
  subtitle?: string
  indexTitle?: string
  path?: string
  children: Track[]
  /** Presentation, separated from content. See {@link SectionStyle}. */
  style?: SectionStyle
}

interface Track {
  // …content fields…
  // (ResolvedTrack extends Track and narrows `style` to SectionStyle —
  // the page tier: a resolved page is a container, so it may default
  // everything its sections can declare. Legal covariant override;
  // Nitro flattens it.)

  /**
   * Unavailable — a content-state fact beside `favorited` and
   * `live`, with full behavioral weight (content facts may carry
   * behavior; style never does): a disabled item never plays — tap
   * refused, auto-advance and next/previous skip it, voice search
   * won't match it, queue expansion excludes it.
   *
   * Rendering ladder, never a trap: **grayed + inert** where the
   * surface can draw it (CarPlay rows iOS 15+, tile elements
   * iOS 26+) → **hidden** where it can't (Android Auto, the pre-26
   * legacy image row) — never a normal-looking dead control.
   * Hiding is behavior-safe because the item is inert everywhere
   * regardless; the cost is losing the "Available at 9 PM" tease on
   * surfaces that hide, so put the reason in the title for the ones
   * that gray. Applied at page (re-)serve, like style.
   *
   * @default false
   */
  disabled?: boolean

  /** Item properties (cascading) + the page-layout promise (display). */
  style?: TrackStyle
}

interface ResolvedTrack extends Track {
  /** The page tier: page-wide defaults for sections. */
  style?: SectionStyle
}

}

  "title": "Results",
  "style": { "display": "grid", "imageShape": "circular" },

}

2. Why CSS-adjacent

CSS concept Here
Content / presentation separation title, path, children are content; everything about pixels lives in one style block instead of scattered among content fields.
Inapplicable declarations are inert grid-template on a non-grid element does nothing; gridWrap: false on a list section does nothing. No tagged unions, no compile-time gating — tolerance is the semantics, and it is the same "silently ignored where unsupported" rule the library already applies across surfaces. One rule now covers both axes: properties a style type doesn't use and properties a surface can't render are ignored identically.
The cascade Per-property resolution — item properties track ?? section ?? page ?? default, container properties section ?? page ?? default (the page tier is ResolvedTrack.style: a resolved page is a container). display is positional — each holder describes its own children (CSS's inner display type) — and never cascades item-to-container. The typed sets: TrackStyle holds the cascading item properties plus the positional display, and SectionStyle extends TrackStyle makes every one defaultable at section level by construction (a missing section default is unrepresentable — how the cardTint and cardImage omissions were caught). Container properties (element class, item-level knobs) live only on SectionStyle and don't cascade. One capability is deliberately removed rather than generalized: the shipped per-track outer display hint (a single grid tile inside a list section, expressible on projected Android Auto today) has no home in this model — CarPlay's containers are homogeneous anyway; recorded in the rejected-shapes log. Alias promotion collapses alias→canonical within a level, then cascades — canonical never beats a lower level's alias.
Unprefixed properties CSS ran the vendor-prefix experiment (-webkit-, -moz-) and the ecosystem's verdict was that prefixes were a mistake: they leak into content, ossify, and unprefixing later is a painful migration cycle — exactly the @deprecated promotion machinery an earlier draft designed. Properties are born unprefixed; renderers adopt them over time; the per-property applicability table is the compatibility story (caniuse, in spirit).
Aspirational rendering A declaration states intent; each renderer applies what it understands. A phone UI honoring gridWrap: false as a horizontal scroller is using the schema as intended — no tier boundary to trespass.

What the block model deliberately gives up: compile-time invalid-combination errors (the tagged-union drafts had them). CSS-consistent answer: combinations aren't invalid, they're inert — cardTint without a card treatment simply doesn't paint. Authoring mistakes surface in the renderer, like CSS, and the docs' applicability table is the reference.

3. The wire

style is one nested struct with all-optional fields — not a union, so none of the variant costs that killed the style: 'list' | { type: … } sketches apply: no discriminator decoding, no multi-struct codegen, no per-variant duplication. SectionStyle and TrackStyle are ordinary Nitro structs like TrackRequest. Unknown keys inside the block are ignored by the native decoders like unknown keys anywhere — the expand/contract property is preserved.

No string shorthand. style: 'grid' (string) does not survive as sugar for style: { display: 'grid' } — one spelling, no dialect normalization on three platforms. This is a breaking change to the current branch shape (string styles on Section and Track), all unshipped.

Family prefixes scope by mode (what it means); the rejected vendor prefix scoped by platform (who renders it).

6. Rejected shapes — the decision log

1. imageRow pseudo-track

The pre-sections model. Platform class name leaked into the domain; a second grouping mechanism that didn't compose with the first. Retired by ADR 0010.

2. style: 'grid-row'

Named iOS's rendering geometry, not intent; read as a modifier of grid; collides with the CSS grid-row property. Renamed to rail.

3. style: 'rail' (as a style kind)

Single-line is an axis of grid, not a third kind — condensed shelves and card shelves exist, so a rail kind would either multiply (card-rail, condensed-rail) or block those compositions. Became the gridWrap: false property.

4. carPlay*-prefixed hint fields + promotion policy

The vendor-prefix design: options as carPlayGridSingleLine-style flat fields, promoted with @deprecated when a second renderer arrives. CSS ran this experiment and regretted it: prefixes mislabel general presentation intents as platform-private, and the promotion machinery is the painful -webkit--to-standard migration cycle by another name. Properties are born unprefixed; the applicability table is the compatibility story.

5. Flat unprefixed fields on Section (no block)

The intermediate rework: gridWrap: false, imageShape etc. as loose Section fields. Mixes presentation into the content object, needs tagged-union authoring types for co-location, and leaves per-field precedence rules instead of one cascade. The block groups presentation where CSS puts it, and the cascade states the override rule once.

6. grid: boolean | 'rail' (replacing style for tiles)

Dissolves the kind enum; future kinds become sibling boolean-ish fields, making { grid: true, cards: true } representable nonsense.

7. style: 'list' | { type: 'grid', … } (string/object mix)

Sugar dialects: the string forms survive as shorthand, so three platforms normalize two spellings of every style forever. The adopted model keeps one spelling by dropping the string entirely.

8. style as a discriminated union of per-type objects

The tagged-union reading of the nested sketches: per-variant structs, discriminator decoding, per-variant duplication of shared options, homeless per-track overrides. The declaration-block model keeps the nesting and discards the union: one struct, all-optional, cascade for overrides — which is what the sketches were reaching for all along.

9. Cards as a style kind

A card is a tile treatment, not a kind of section — as a kind it couldn't compose with single-line (the hero row needed a fifth style). Became gridTile: 'card'.

10. condensed: boolean (sibling boolean)

Card/condensed are mutually exclusive element families; the gridTile enum makes the conflict unrepresentable. (Condensed per-track was separately impossible: element families are container-homogeneous.)

11. Condensed as a style kind

Density is an axis, not a kind: condensed shelves and condensed grids both exist, and a 'condensed' kind would erase the underlying intent non-CarPlay surfaces need for fallback.

12. Per-item outer display (the shipped AA hint)

A track hinting its own tile shape inside a differently-styled section — expressible on projected Android Auto today, removed here: CarPlay containers are homogeneous (unrenderable there), it made display's cascade surface-conditional, and it collided with inner-display semantics. The per-item AA hint now derives from the section resolution.

13. Imperative setters where declarative fields suffice

General pattern, decided per-field elsewhere (tab badges); recorded here because it recurs. Declarative blocks + cascade is the same stance applied to styling.

7. Implementation sketch (when confirmed)

  1. Spec: SectionStyle becomes a struct (display, gridWrap: false; gridTile and the card* properties land with their features — no dead fields); TrackStyle becomes a struct (display preserving today's AA hint; imageShape/tint land with theirs). 'rail' is gone. Codegen + stub mirrors.
  2. Cascade: one resolver per platform — item properties track ?? section ?? page ?? default, container properties section ?? page ?? default, with display on an explicit positional deny-list (never item-cascaded). The completeness test splits accordingly: every cascading key read by every resolver; every positional key provably excluded (Nitro erases extends; nothing else catches either omission).
  3. iOS: SectionPresentation keys off display == .grid + gridWrap + gridTile: 26+ picks the element family (plain / card / condensed) and line mode; pre-26 drops the treatment and keeps the layout — gridWrap: false → legacy image row (whatever the treatment), wrapping → list. The cascade resolver threads the resolved TrackStyle into createListItem (which today never receives the section, and has one legitimately section-less caller to tolerate). The artwork loader reads cardImage for the target size (maximumFullHeightImageSize).
  4. Android: isTileSection = style?.display == GRID; MediaExtrasBuilder reads the cascade. Track.childrenStyle: resolved — replaced by TrackStyle.display (inner semantics). Research verdict (source-verified): the AOSP-derived AAOS media UIs — including mainstream GAS cars' OEM skins — ignore per-item SINGLE_ITEM hints and honor only parent/root-level hints, so a parent-level emission is required, not legacy. It now derives from the browsable handle's style.display (the page-layout promise); per-item hints derive from the section resolution (section ?? page); root-level defaults arrive with the future config tier, completing all three AA levels. The legacy CONTENT_STYLE_SUPPORTED opt-in is confirmed dead — nothing to add. Delete the childrenStyle field; keep the BROWSABLE/PLAYABLE key emission, re-sourced from the handle's declared promise (emitted only when declared). Evidence: Google's content-styles docs and the AOSP reference BrowseAdapter (parent → root → LIST; no SINGLE_ITEM handling). Also here: ResolvedTrack.toTrack() becomes an explicit SectionStyle → TrackStyle projection (drops container props — Nitro flattens extends), and disabled items are omitted from AA children per the rendering ladder (AA can't gray → hide).
  5. Web/examples: JSON authoring moves to blocks; example phone UIs read display (and may honor gridWrap: false as the scroller — intended usage).
  6. Docs: CONTEXT.md — Section entry's style sentence, Rail entry retired (Avoid list migrates); a Style glossary entry (declaration block, cascade, inert-when-inapplicable); verify the Artwork entry still holds (it does after the artworkRendering/imageShape renames — role word for library-defined, passthrough keeps Apple's term); ADR 0010 amendment (this is a real model change — possibly ADR 0011); guides; audit report decisions panel: amended (done); issues #56, #131 (and the naming discussions in #125/#126) updated to point here.
  7. Wire note: string styles never shipped in a release — but stale JSON does not degrade safely by default: both native decoders throw on type mismatch (a string where the block is expected kills the whole page on Android and the whole persisted playback state on iOS). Tolerant decoding is mandatory: decode-to-nil on mismatch (never decode-to-block — no dialect), precedent JsonArtwork's hand-written init. Android's PlaybackStateStore string-name encoding of styles becomes nested-object encode/decode — decided: restored queues keep their style blocks and disabled (visible fidelity across process death beats a smaller blob).
  8. Spec-level tests: a cascade-completeness test (every TrackStyle key read by every platform resolver — Nitro erases extends, so TS can't enforce this) and a dev-mode inert-declaration diagnostic (warn when a declaration can never render: cardTint with no card treatment in scope, gridWrap on a list section) — the recovery for the compile-time gating the block model deliberately gave up.

8. Open questions

  • 'card' vs 'cards' — 'card' favored: the value names what one tile is, matches 'condensed', and doubles as the card* family prefix ("a gridTile value's name is the prefix of the properties it gates").
  • Does the phone-UI example honor gridWrap: false as a scroller (demonstrating intended usage), or stay display-only?
  • Condensed's actual layout (Apple documents only the word) — lab question. gridWrap: false + 'condensed' is specified (condensed elements, allowsMultipleLines: false); whether shape/accessory render in that mode is part of the same lab check.
  • Nitrogen extends-flattening: verified conceptually (ResolvedTrack extends Track ships), but confirm on the new structs at implementation.
  • The page tier (ResolvedTrack.style?: SectionStyle) is now in the design; the app tier (BrowserConfiguration.style?) remains deferred — it is also the natural source of Android Auto's root-level default hints (one bundle, maximum compatibility), which is its promotion trigger.
  • Section.subtitle has two pending meanings (today's view-all label on Android Auto; the audit's proposed CarPlay headerSubtitle) — reconcile when enhanced headers land.
  • Whether accessorySymbol should adopt the sf: URI scheme (making the platform-bound value domain explicit, leaving room for a future mat:) — parked idea.
