## Key Architecture Points

### Nitro Module Pattern

- `HybridAudioBrowser` is the single entry point, implementing `HybridAudioBrowserSpec`
- Unified interface for both browsing and playback functionality
- Direct JS-native method calls (no event emitters)
- ~50 callbacks as closure properties organized into categories:
  - **Browser** (4): `onPathChanged`, `onContentChanged`, `onTabsChanged`, `onNavigationError`
  - **Player** (14): `onPlaybackProgressUpdated`, `onPlaybackActiveTrackChanged`, `onPlaybackPlayingState`, etc.
  - **Remote** (16): `onRemotePlay`, `onRemotePause`, `onRemoteNext`, etc.
  - **Remote Handlers** (14): `handleRemotePlay`, `handleRemotePause`, etc. (optional JS overrides)
  - **Other** (8): `onOptionsChanged`, `onFavoriteChanged`, `onNowPlayingChanged`, `onOnlineChanged`, etc.
- Types generated by Nitrogen in `nitrogen/generated/ios/swift/`

### Playback Core: Player over PlayerEngine

The playback core is two `@MainActor` types, split by what SwiftPM can compile:

- **Player** (`Player/Player.swift`) is the façade the bridge, CarPlay and Siri call, and holds
  every playback decision. It holds the `PlaybackState`, the play intent, the `ErrorStatus` and
  the current **Load**, runs `transition(_ event:)`, and publishes each change once through
  `publish()` to `PlayerCallbacks` (HybridAudioBrowser). It owns `QueueManager`, `RetryLoop`,
  `SleepTimerManager` with `VolumeFader`, `DeferredSeek`, `PlaybackPersistence` and two
  `PlaybackTimer`s. Seeking, reloading, stall and network recovery, the end-of-item judgement and
  the cold-start resume are all here, fully SwiftPM-tested against a mock engine.
- **AVPlayerEngine** (`AVPlayerEngine.swift`) implements `PlayerEngine`, the Player's one seam to
  the media stack. It owns the `AVPlayer`, its `PlayerObserver` and the current item's
  `ItemObserver`, `MediaLoader`, `SilentAudioPrimer`, `NowPlayingInfoController`,
  `NowPlayingUpdater` and `RemoteCommandController`. It carries out what the Player decides and
  reports what it observes as `EngineEvent`s; it holds no playback policy.

HybridAudioBrowser keeps both: `player` for playback, `engine` for what only AVFoundation has
(now playing, buffering, volume, remote commands).

The state machine itself is a **pure function**: `nextPlaybackState(from:on:)` in
`PlaybackStateMachine.swift` is a transition table over the `PlaybackEvent` enum (`PlaybackEvent.swift`).
State-related guards live in the table; context-related guards (`asset != nil`, `nearTrackEnd`, etc.)
live at the call site that decides whether to fire the event.

HybridAudioBrowser implements `PlayerCallbacks` (the Player's Nitro-typed events) and
`AVPlayerEngineCallbacks` (remote commands, metadata and now-playing changes, which carry
AVFoundation types).

### Data Flow

1. **JS → Native**: Direct sync/async method calls via Nitro
2. **Native → JS**: Callback properties invoked from native code (Player and engine events route through HybridAudioBrowser)
3. **Browser → Player**: `navigateTrack()` uses TrackSelector to resolve track selection (contextual URL expansion, queue reuse, handler interception) and then executes the resulting PlaybackIntent
4. **State Machine**: a PlaybackEvent triggers a deterministic transition via `Player.transition(_ event)`; the Player queries `nextPlaybackState(from:on:)`, applies side effects through its `PlayerEngine`, updates timers, and publishes
5. **Player → Queue**: the Player delegates queue operations to QueueManager (pure state, no AVPlayer knowledge); each mutation returns a `QueueChange`, which `afterQueueMutation` publishes
6. **Player → Error/Retry**: RetryLoop classifies each failure (`PlaybackFailure`) and either backs off and reloads or reports it, waiting out offline spells via NetworkMonitor
7. **Engine → MediaLoader**: AVPlayerEngine delegates URL resolution and asset loading to MediaLoader; receives its results as `MediaLoader.Event`s
8. **Engine → NowPlayingUpdater**: AVPlayerEngine calls NowPlayingUpdater for track metadata and artwork; NowPlayingUpdater updates NowPlayingInfoController (playback dynamics auto-publish via MPNowPlayingSession) and reads the Player as its `NowPlayingSource`
9. **Player → DeferredSeek**: a seek that arrives before the AVPlayerItem is ready is held as pure state; the Player issues it once the engine reports the item ready, and the load becomes ready when it lands
10. **Platform → Observers → Player**: KVO and NotificationCenter reach the engine's observers, which the engine reports to the Player as `EngineEvent`s

### Thread Safety

- `HybridAudioBrowser.onMainActor()` ensures player operations run on main thread
- `Player`, `AVPlayerEngine`, `BrowserManager`, `TrackSelector`, all observers, controllers, and Player-owned managers are `@MainActor`
- `DeferredSeek`, `ShuffleOrder`, and the judgement/criteria value types are plain (non-`@MainActor`) value/data types
- `LRUCache` is main-actor isolated; `HttpClient` and `NetworkMonitor` are `@unchecked Sendable`
- `UncheckedSendableBox` wrapper for non-Sendable return types from `onMainActor()` calls

### Relationship to RNTP

This codebase is adapted from react-native-track-player. Key differences:

- **Bridge layer removed** - No `TrackPlayerModule.swift`, no Obj-C bridge
- **Nitro types used** - `Track`, `PlayingState`, events from nitrogen/generated
- **Browser added** - Navigation, routing, HTTP client (not in RNTP)
- **Unified API** - Browser and player merged into single HybridAudioBrowser
- **URL Resolution** - Media and artwork URL transforms via configuration

## Implementation Notes

### Track Type

The Nitro `Track` has:

- `url: String?` - Browsable path (for navigation)
- `src: String?` - Playback URL (for AVPlayer)
- `artwork: String?` - Artwork URL
- `artworkSource: ImageSource?` - Detailed artwork config

Use `track.src ?? track.url` for AVPlayer URL.

### Callbacks

HybridAudioBrowserSpec defines ~50 callbacks as properties:

```swift
// Browser callbacks (4)
var onPathChanged: (String) -> Void = { _ in }
var onContentChanged: (ResolvedTrack?) -> Void = { _ in }
var onTabsChanged: ([Track]) -> Void = { _ in }

// Playback callbacks (14)
var onPlaybackProgressUpdated: (PlaybackProgressUpdatedEvent) -> Void = { _ in }
var onPlaybackActiveTrackChanged: (PlaybackActiveTrackChangedEvent) -> Void = { _ in }

// ...etc

// Remote callbacks (16) - fire events to JS
var onRemotePlay: () -> Void = {}
var onRemotePause: () -> Void = {}

// ...etc

// Remote handlers (14) - optional JS overrides for default behavior
var handleRemotePlay: (() -> Void)?     // If set, overrides default
```

Callbacks are set from:

- `TrackPlayerCallbacks` protocol methods (player events)
- `BrowserManager` emitters (navigation events)
- `NetworkMonitor.onChanged` (connectivity)
- `SleepTimerManager.onChanged` (sleep timer)

### Promises

Async methods return `Promise<T>`:

```swift
func setupPlayer(options: NativeSetupPlayerOptions) throws -> Promise<Void>
```

Use Nitro's Promise helpers for async operations.

#### Chaining `.then`/`.catch` on a JS-callback Promise from an `@MainActor` type

When you invoke a JS callback that returns a `Promise<T>` (a `formatNavigationError` / now-playing
formatter, etc.) and chain `.then`/`.catch`, **Nitro resolves that promise on the JS thread**, not
on main. `Promise.then(_:)` takes a non-`@Sendable` closure, so inside an `@MainActor` type the
resolver is _inferred_ `@MainActor`-isolated — and running a main-isolated closure off-main traps:
`_swift_task_checkIsolated` → `dispatch_assert_queue_fail` (crashes on the
`com.facebook.react.runtime.JavaScript` thread).

Mark the resolver `@Sendable` to break the isolation inheritance, then hop back to the main actor
for any main-isolated work:

```swift
formatter(params)
  .then { @Sendable [weak self] result in
    guard let self, let result else { return }
    Task { @MainActor in self.apply(result) }
  }
  .catch { @Sendable error in
    let message = error.localizedDescription      // compute off-main; only a String crosses
    Task { @MainActor in self?.logger.error("formatter failed: \(message)") }
  }
```

This is the same reason the artwork callback in `NowPlayingUpdater` is `@Sendable`. A direct
`self?.someMainActorMethod(...)` call inside `.then` only _appears_ to work when that particular
promise happens to resolve on main — it's a latent crash otherwise.

### Logging

**Always use `os.Logger` instead of `print()` for debugging.**

```swift
import os.log

class MyClass {
    private let logger = Logger(subsystem: "com.audiobrowser", category: "MyClass")

    func doSomething() {
        logger.debug("Debug message")
        logger.info("Info message")
        logger.error("Error message")
    }
}
```

- Use `logger.debug()` for development debugging
- Use `logger.info()` for general information
- Use `logger.error()` for errors
- See `HttpClient.swift` for a complete example
